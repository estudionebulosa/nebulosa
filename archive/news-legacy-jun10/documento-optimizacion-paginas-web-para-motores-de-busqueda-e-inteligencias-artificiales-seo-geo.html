Los 3 documentos esenciales para crear una App con un Agente de IA

Te muestro como trabajan las grandes empresas de software, pero simplificando al maximo para que crees aplicaciones de manera facil utilizando Inteligencia Artificial

Cuando trabajas con un agente de IA, la claridad y la estructura lo son todo. Si le entregas un documento desorganizado, la IA inventará funciones o cometerá errores. Para crear una aplicación básica utilizando un agente de IA, te voy a enseñar como estan estructuradas las empresas de software. Para que la IA actue como lo harian las partes de la empresa.

Puedes reducir todo el proceso a solo 3 documentos prácticos diseñados específicamente para que una IA los entienda a la perfección y genere el código sin perderse.

A continuación, analizaremos las plantillas y ejemplos basados en la creación de una app sencilla: un reloj tipo pomodoro, que nos avisa con un cronometro, que nos ayuda a crear pausas y mejorar la concentración. "App para cuidar la higiene visual, que nos avisa cada 20 minutos que hagamos una pausa de 20 segundos ".

Documento 1: El PRD (Requisitos del producto) (El "Qué hace" la app)

El PRD o Product Requeriments Documents de sus siglas en ingles

Este documento le explica a la IA el objetivo de la aplicación y las reglas exactas que debe programar. Debe ser directo y libre de ambigüedades técnicas.

Ejemplo de Plantilla de Requisitos para la IA:

Proyecto: App Control Concentración (Web minimalista)

Objetivo: Permitir al usuario periodos de maxima concentración y avisarles de descasos.

Funciones requeridas:

  1. Formulario de ingreso: Una pantalla completa donde aparecera el tiempo en grande con el tiempo transcurrido, y un circulo concentrico que se vaya completando Un campo de texto para el "Periodo" (ej. Concentración) , esos mismos campos se cambiaran cuando pase el tiempo de concentración y se mostrara el tiempo de descanso y en el campo "Periodo" (ej. Descanso )
  2. Botón de guardar: Al hacer clic, guarda el gasto en una lista visible.
  3. Lista de gastos: Muestra los gastos guardados con un botón de "Eliminar" al lado de cada uno.
  4. Contador total: Un texto grande que sume automáticamente todos los montos de la lista.

Reglas de validación:

  • El campo "Monto" no puede aceptar letras ni números negativos.
  • Si el usuario intenta guardar con campos vacíos, mostrar un mensaje de error.

Documento 2: El Prompt de Arquitectura y Stack (El "Cómo se construye")

Las IA programan mejor si les defines exactamente qué tecnologías usar y cómo estructurar el código. Esto evita que use librerías desactualizadas o incompatibles.

Ejemplo de Plantilla de Arquitectura para la IA:

Rol: Actúa como un Ingeniero de Software Full-Stack Senior experto en desarrollo ágil.

Tecnologías a usar:

  • Frontend: HTML5, CSS3 (usando el framework Tailwind CSS por CDN para el diseño) y JavaScript nativo (Vanilla JS).
  • Almacenamiento: localStorage del navegador para que los datos no se borren al recargar la página.

Estructura del Código requerida:

  • Genera todo el proyecto en un único archivo llamado index.html para facilitar la prueba inmediata.
  • El código JavaScript debe estar ordenado, comentado y al final del archivo.
  • Usa funciones limpias para: agregarGasto(), renderizarLista(), calcularTotal() y eliminarGasto().

Documento 3: El Wireframe de Texto y Flujo (El "Cómo se ve")

Como el agente de IA lee texto plano, debes describir la interfaz de forma visual pero escrita, detallando la distribución y el flujo de navegación preciso de las pantallas.

Ejemplo de Plantilla de Flujo para la IA:

Distribución de la interfaz (Diseño Limpio y Centrado):

  • Encabezado: Título "Mi Tarjeta de Gastos" en negrita, color azul.
  • Bloque Central (Tarjeta): Un contenedor blanco con bordes redondeados y sombra suave. Dentro lleva:
    • El contador: "Total Gastado: $0.00" (Texto grande y destacado).
    • El formulario: Dos inputs en línea (Concepto | Monto) y un botón verde que dice "+ Añadir".
  • Bloque Inferior: La lista de gastos. Cada fila debe tener el nombre a la izquierda, el precio al centro y un botón rojo con la palabra "X" a la derecha.

Flujo del usuario:

  1. El usuario abre la página -> Ve el total en $0.00 y la lista vacía.
  2. Escribe "Café", pone "3.50" y pulsa "+ Añadir" -> El formulario se limpia, el foco vuelve al primer input, el café aparece abajo y el total cambia a $3.50 de forma inmediata.
